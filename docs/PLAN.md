# ucode admin frontend — план v1

Итог грилинг-сессии 2026-08-14. Всё, что здесь записано, — принятые решения,
а не варианты. Термины — в [CONTEXT.md](../CONTEXT.md).

## Почему переписываем

Замеры старого репозитория (`ucode-frontend/ucode_admin_frontend`):

| Что | Цифра |
|---|---|
| Код | ~290 000 строк, 100% JSX, 0 TypeScript |
| Runtime-зависимости | ~200 |
| UI-киты одновременно | MUI, Chakra, Mantine, antd, rsuite |
| Rich-text редакторы | CKEditor, EditorJS, Jodit, Quill, draft-js |
| Одна и та же таблица написана | 3 раза (`Objects` 57k, `views` 59k, `table-redesign` 15k) |
| Поколений формы | 4 (`FormElements`, `-backup`, `Optimization`, `New`) |
| Слайсов в redux-persist → localStorage | ~30 |
| Вызовов `useQuery` | 415, из них с `staleTime` — **3** |
| Имён кэша для одних и тех же строк | 4 (`GET_OBJECT_LIST`, `GET_OBJECTS_LIST`, `..._ALL`, `..._WITH_RELATIONS`) |
| Копий логики refresh-токена | 4 файла |
| Ветвлений по legacy-флагам | 359 в ~130 файлах |

Связь с заявленными проблемами:

- **Лишние запросы** — `staleTime` по умолчанию 0 → рефетч на каждое монтирование.
- **Память 1.5 ГБ** — 4 независимых кэша одних данных + 30 слайсов в localStorage + все UI-киты и редакторы в бандле.
- **Лишние ререндеры и тормоза** — фильтры и пагинация в глобальном сторе; redux-persist пишет в localStorage синхронно на каждый dispatch; MUI генерирует CSS в рантайме на каждый рендер ячейки.
- **Чеки на старые версии** — 359 ветвлений растут из трёх булевых полей Project в бэкенде.
- **Случайные разлогины** — 4 копии refresh-логики → параллельные 401 дают N одновременных refresh, токен ротируется, лишние сессии умирают.

## Стек

| Слой | Выбор |
|---|---|
| Язык | TypeScript strict |
| Сборка | Vite, React 19, SPA. Без Next.js |
| Пакетный менеджер | pnpm, версия закреплена в `packageManager` |
| Роутинг | TanStack Router — типизированные search-параметры |
| Данные | TanStack Query v5 |
| Глобальное состояние | Zustand, только UI: sidebar, тема. Redux и redux-persist не используем |
| Стили | Tailwind v4 |
| Компоненты | shadcn/ui (Radix) — код в репозитории, не зависимость |
| Таблица | TanStack Table (headless) + TanStack Virtual, рендер свой |
| HTTP | axios, один инстанс на всё приложение |
| Типы API | генерация из `ucode_go_admin_api_gateway/api/docs/swagger.json` (181 path, 222 definition) + ручной слой доменных типов поверх |

Дизайн-системы пока нет — будет создана отдельно.

**Версии зависимостей.** Перед установкой проверяется `npm view <пакет> version`,
ставится последняя стабильная — но только та, которую поддерживает остальной
инструментарий. Отклонения от последней версии сопровождаются причиной
в `CLAUDE.md`. Бета и rc не ставим.

## Состояние: где что живёт

| Что | Где |
|---|---|
| Фильтры, сортировка, размер порции, активный View, открытый Item | **URL (search params)** |
| Данные с бэкенда | **TanStack Query**, `staleTime: 60s` |
| Sidebar collapsed, тема | **Zustand** |
| Всё остальное | `useState` |
| localStorage | только refresh-токен и пара UI-префов |

Форма URL — см. [ADR-0001](adr/0001-environment-in-session-not-url.md):

```
/m/:menuId?view=<viewId>&limit=&sort=&filter=
```

Номера страницы в адресе нет: строки догружаются прокруткой (см. таблицу
ниже — бесконечный скролл в v1), и `page` в ссылке означал бы место,
которого у бесконечного списка не бывает. `limit` остался: это размер
порции, и он же настройка view.

Путь — какой пункт меню открыт: набор View принадлежит пункту меню
(`GET /v3/menus/{menuId}/views`), а не таблице. Query — как показан.

Project и Environment в URL отсутствуют: оба лежат в серверной сессии,
и одновременно двух не бывает. Смена окружения =
`V2RefreshTokenForEnv` + `queryClient.clear()` + навигация.

## Структура и границы

```
src/
  app/            провайдеры, роутер, глобальные стили
  routes/         файловые маршруты. Только композиция
  features/
    auth/  table/  view/  item/  sidebar/  settings/
  shared/
    ui/     shadcn-компоненты
    lib/    утилиты
    api/    http-клиент + сгенерённые типы
```

`table` (схема: Table, Field, Relation) и `item` (данные: список, Drawer,
создание) — **разные фичи**: разный жизненный цикл, права и кэш.

Внутри фичи плоско. Подпапки `api/ components/ model/` заводим, когда
файлов больше десятка, не заранее.

### Правила, проверяемые линтером в CI

1. `shared/` не импортирует ниоткуда.
2. `features/*` импортирует только `shared/` и `index.ts` соседней фичи — никогда её внутренности.
3. `routes/` импортирует фичи. Фичи не импортируют `routes/`.
4. `useQuery` / `useMutation` запрещены вне `features/*/api/`.
5. Ключи кэша — только типизированная фабрика, строковых литералов нет.

Правило, проверяемое только чтением, не соблюдается. Старый ucode — доказательство.

## Auth

Устройство сессии (`ucode_go_auth_service/grpc/service/session_service_v2.go`):

- В JWT: `project_id`, `role_id`, `client_type_id`, `user_id`, `tables`, `login_table_slug`, `client_platform_id`.
- Environment — заголовок `Environment-Id` (только v2-вариант написания) + поле в серверной сессии.
- Смена окружения мутирует ту же сессию и выпускает новую пару токенов.

Решения:

- **Один** http-клиент вместо восьми. Токен, `project_id`, `Environment-Id` — в одном интерцепторе.
- **Один** refresh с мьютексом: параллельные 401 ждут один запрос обновления.
- Способы входа в v1: **email+пароль, Google, invite-регистрация, восстановление пароля**. Phone+OTP — v1.1. ESP/ЭЦП — не переносим.
- Мульти-таб на разных окружениях невозможен — известное ограничение, чинится только на бэкенде.

## i18n и тема

В ucode два независимых механизма, которые старый код смешивал:

### Язык интерфейса

Языки v1: **ru, en, uz**. `ar` не берём — в старых локалях он переведён
наполовину и держит дыры в интерфейсе.

Переводим **сами по ходу работы**. Старые `public/locales/*.json`
не переносим: они рассинхронизированы (ru 299 ключей, en 254, ar 176).
Английскую формулировку можно брать из захардкоженных строк старого кода —
там она во многих местах уже написана.

### Мультиязычные значения полей

[[Field]] с `enable_multilanguage`: значение хранится как `{ru: ..., en: ...}`,
список языков задаётся на уровне Project.

В v1: чтение и запись на текущем языке интерфейса + переключатель языка
в Drawer. Фильтрация и сортировка по языку — v1.1.

### Тёмная тема

В v1. Это не фича, а дисциплина: **ни одного захардкоженного цвета**,
включая собственный грид. Всё через токены Tailwind. Стоит ноль с первого
дня и дорого — потом.

## Одно имя — один источник

Бэкенд отдаёт одно и то же под разными именами и в разных местах. Старый
фронт на это отвечал чтением всех вариантов сразу:

```js
// views/Objects/DrawerDetailPage/OldDrawerFormDetailPage.jsx:145
field?.enable_multilanguage || field?.enable_multi_language
  || field?.attributes?.enable_multi_language
```

Истина здесь одна и определяется схемой БД:

| Вариант | Что это на самом деле |
|---|---|
| `field.enable_multilanguage` | **колонка** (`000001_init_tables.up.sql:80`) и типизированное поле (`field.proto:43`) — **истина** |
| `field.attributes.enable_multi_language` | ключ внутри свободного JSONB-мешка `attributes`, никем не валидируется |
| `field.enable_multi_language` | не существует в схеме |

Живой баг старого ucode как иллюстрация: `FieldCreateModal` записывает
`enable_multilanguage`, а рендер Relation-полей (`RelationField.jsx:514`)
читает `attributes.enable_multi_language`. У поля, созданного через UI,
мультиязычность в связях не работает.

**Правило.** Нормализация происходит **один раз, в `features/*/api/`**.
Наружу отдаётся ровно одно имя и ровно одна форма. Ни один компонент,
хук или ячейка не пишет `a || b || c.d`. Если непонятно, какое из имён
истинное — истина ищется в схеме БД и proto, а не выбирается голосованием
через `||`.

Таких мест в старом коде много. Каждое разбирается **при переносе фичи**,
и результат — один нормализованный тип в `features/*/model/`.

## Порядок работы

1. Каркас: стек, границы, линтер, http-клиент, генерация типов
2. Auth
3. Sidebar
4. Constructor — урезанный: Table, Field, Relation
5. TABLE view: виртуализация, inline-редактирование
6. Настройки View: колонки, фильтры, сортировка
7. Drawer
8. Relation-поля в таблице и в Drawer
9. Settings — 3 модуля из 21: `Account`, `ProjectSettings`, `PermissionsRoleDetail`

Пункт 4 вставлен, потому что без него новый пользователь не может создать
ни одной Table, и v1 оказывается оболочкой вокруг пустоты.

Язык интерфейса, тёмная тема и мультиязычные поля идут сквозной задачей
через все пункты, а не отдельным этапом.

Не в v1: функции и OpenFaaS, микрофронтенды, website-страницы, остальные
18 модулей настроек, BOARD/CALENDAR/TIMELINE, копипаст диапазона ячеек.

## Старый репозиторий для ИИ-агентов

Доступ асимметричный:

- **Читать разрешено** ради ответа на вопрос «что»: что делает фича, какие эндпоинты, какие поля в ответе, какие крайние случаи покрыты.
- **Копировать запрещено**: код, структура файлов, имена из запретного списка `CONTEXT.md`.

Формулировка правила: *старый репозиторий — спецификация поведения, а не
исходник. Из него переносится «что», никогда «как».* В нём есть мёртвый код,
обходные пути и баги — он не эталон.

### Где смотреть эталонное поведение

| Фича v1 | Референс в старом репозитории |
|---|---|
| View и его настройки | `src/views/views/` — последнее поколение |
| Drawer | `src/views/views/components/DrawerDetailPage/` |
| Settings | `src/views/SettingsPopup/modules/` |
| Constructor | `src/views/Constructor/Tables/` |
| Auth | `src/views/Auth/components/LoginFormDesign/` |
| Sidebar | `src/components/LayoutSidebar/`, `src/hooks/useSidebarElements` |

Не референс: `views/Objects/`, `views/table-redesign/`, `components/DataTable/`,
`components/FormElements*` — предыдущие поколения.

### Обязательное для агента

1. Читать `CONTEXT.md` перед задачей.
2. Границы и запрет `useQuery` вне `api/` — правилами ESLint.
3. Хук, блокирующий коммит при падении линта границ.
