# 4. Мультиязычность поля включается только при создании

Дата: 2026-08-18
Статус: принято

## Контекст

Мультиязычное поле — это НЕ карта значений по языкам, а несколько
колонок: `title_en`, `title_cyr` (CONTEXT, [[Multilanguage Field]]).
Заводит их шлюз, и только в момент создания поля:

```go
// api/handlers/v2/field.go:84
if fieldRequest.EnableMultilanguage {
    if fieldRequest.Type == "SINGLE_LINE" || fieldRequest.Type == "MULTI_LINE" {
        if len(languages.GetLanguage()) > 1 {
            for _, value := range languages.GetLanguage() {
                fields = append(fields, SetTitlePrefix(fieldRequest, value.ShortName, …))
            }
        }
    }
}
```

`SetTitlePrefix` дописывает к слагу `_<код языка>`. PUT поля ничего
подобного не делает — он пишет колонку `enable_multilanguage` и всё.

Второе: object_builder НЕ сохраняет этот флаг при вставке — колонки
`enable_multilanguage` нет в INSERT (`storage/postgres/field.go:116`).
Поле, только что созданное мультиязычным, возвращается с `false`.

Отсюда два вывода, которые выглядят противоречащими CONTEXT
(«единственное истинное имя признака — `field.enable_multilanguage`»):

1. Переключатель мультиязычности у СУЩЕСТВУЮЩЕГО поля работать не может:
   флаг встанет, а колонок `title_en`/`title_cyr` не появится.
2. Опознавать языковую группу по флагу нельзя: у свежесозданных полей
   его нет.

Старая админка предлагала этот переключатель всем и всегда — и он
молча не работал.

## Решение

**Включается при создании.** Флажок «Мультиязычное» стоит на экране
выбора типа поля, рядом с именем и слагом, и виден только у проекта
с двумя и более языками данных.

**Снимается — у существующего.** Переключатель в настройках поля
показывается, только если поле УЖЕ мультиязычное: снять признак можно,
включить — нет.

**Опознаётся формой набора, а не флагом.** Языковой группой считается
база слага, у которой в наборе есть хотя бы два языковых варианта
(или один, но помеченный флагом) — `languageGroups` в
`features/table/model/multilanguage`. Флаг остаётся сигналом, но не
единственным.

## Последствия

Сделать существующее поле мультиязычным нельзя — только завести новое
и перенести значения. Это цена, и она честная: обратное обещание в
старой админке кончалось полем, у которого признак стоит, а языков нет.

Одиночное поле со слагом вида `title_en` (заведённое человеком, а не
шлюзом) языковой группой не считается и показывается как есть. Иначе
колонка молча теряла бы «en» в подписи.

## Что нужно от бэкенда

Две правки, каждая снимает по ограничению:

1. Перечислить `enable_multilanguage` в INSERT поля
   (`storage/postgres/field.go:116`) — тогда признак переживёт создание,
   и опознавать группу по форме набора будет не обязательно.
2. Заводить недостающие языковые колонки при UPDATE, если признак
   включили у существующего поля, — тогда переключатель можно вернуть
   в настройки поля.
