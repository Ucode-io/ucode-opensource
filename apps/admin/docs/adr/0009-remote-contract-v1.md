# 9. Договор микрофронтенда, версия 1

Дата: 2026-08-26
Статус: принято

## Контекст

Микрофронтенды ucode собраны кто во что горазд, и разброс обнаружился
только когда их начали открывать в новой админке. По четырём живым
проектам на машине:

| Проект | exposes | React | @originjs |
|---|---|---|---|
| `client_app_a1b2c3` | `./App` | 18.3.1 | ^1.4.1 |
| `ucode_template_react` | `./App` | 18.3.1 | ^1.4.1 |
| `new-crm/crm_app_d4e5f6` | `./App` | 18.3.1 | ^1.4.1 |
| `legacy_test-master` | `./Page` | 18.3.1 | ^1.2.3 |

Наш загрузчик просил только `./Page` — то есть три из четырёх
не открылись бы вообще, и ни один из них не собран под React 19.
При этом бэкенд заводит новые микрофронтенды **форком шаблонного
репозитория** (`ucode_go_function_service/api/handlers/mcp_project.go:106`,
`GitlabProjectIdMicroFrontReact`), а тот экспонирует `./App`. То есть
разброс воспроизводится сам собой при каждом создании.

Нужны две вещи сразу: открыть всё, что уже есть, и задать одну форму
тому, что появится дальше.

## Решение

**Ремоут сам говорит, какого он поколения** — модулем `./ucode`:

```js
export const meta = { contract: 1, react: "19" };
```

Хост пробует его загрузить; отказ означает «старое поколение», а не
сбой. Пробовать безопасно: рантайм кэширует модуль по имени ремоута,
а не по экспоузу (`runtime-core/dist/remote/index.js:322-330`), и отказ
`Module.get` нигде не запоминается. Имя `./ucode`, а не `./meta`:
`meta` — слово общего пользования, чужой ремоут мог занять его под своё.

Дальше две ветки:

| | старое поколение | договор 1 |
|---|---|---|
| React | наш React 18 из `vendor/react18` | наш React 19, тот же, что у админки |
| где живёт | свой корень в отдельном узле DOM | прямо в нашем дереве, обычным компонентом |
| имя модуля | `./Page`, потом `./App` | только `./Page` |
| зеркало сессии | пишется ([ADR-0008](0008-legacy-session-mirror.md)) | не пишется |

**Обе версии React лежат в общей области одновременно, и порядок
ключей решает всё.** Это оказалось возможно вопреки первому впечатлению:
потребитель без `requiredVersion` берёт `Object.keys(versionObj)[0]`,
а с `requiredVersion` — ищет подходящую перебором
(`@originjs 1.4.1/dist/index.js:956`). Все существующие ремоуты пишут
`shared: ["react","react-dom"]`, то есть без версии, — значит первой им
обязана достаться 18-я. Поэтому объект версий пересобирается целиком и
всегда по возрастанию мажора, независимо от того, какой микрофронтенд
открыли первым. Закреплено тестом.

Отвергнутая альтернатива — перезаписывать слот перед каждой загрузкой.
Работает, но делает порядок загрузок значимым: ленивый чанк старого
ремоута, спросивший React после переключения, получил бы чужой.

Развести поколения по разным `shareScope` **нельзя**: опция у плагина
есть, но потребитель собирается с вызовом `importShared('имя')` без
второго аргумента (`dist/index.js:521,529,538`) и всегда читает
`default`.

**Контракт закрепляется пакетом**, а не документом: у договора две
половины — загрузчик хоста и то, чем собирают ремоут, — и разъезжаются
они ровно тогда, когда лежат в разных местах.

## Чужой CSS в нашем документе

Обнаружилось на том же живом ремоуте и стоит отдельного разбора,
потому что причина не та, на которую думаешь.

Ремоут поднимает Chakra, и её глобальный сброс уезжает в наш `<head>`
десятками тегов `<style data-emotion="css-global">`: `:where(*)
{ border-width: 0 }`, `button { background: transparent; padding: 0 }`,
`*, ::before, ::after { border-color: … }`. Наши кнопки теряли рамку
и фон, пока открыт чужой экран.

**Дело не в весе селекторов, а в слоях каскада.** Tailwind 4 держит
утилиты в `@layer utilities`, а нелойерные правила бьют любой слой
независимо от специфичности. Поэтому `.border` проигрывает `:where(*)`,
хотя по весу должен выигрывать.

Сужаем чужие правила до поддерева ремоута — и обязательно через
`:where(#…)`, а не `#…`. `:where()` не добавляет веса, и внутри
ремоута порядок остаётся тем, на который рассчитывал его автор.
Проверено обратное: с обычным `#id` сброс поднимается над классами
самой Chakra, и ремоут теряет отступы.

Отдельно — **размер корня**. В собственном `.css` ремоута есть
`html { font-size: 12.8px }`, а наша вёрстка считает в `rem`: после
одного захода вся админка оставалась на 20% мельче. Файл приезжает
`<link>` с чужого адреса, его правила нам не прочитать (CORS), поэтому
не сужаем, а перебиваем своим нелойерным правилом в конце `<head>`
и гасим сам `<link>` при уходе с экрана (удалить нельзя: плагин
помнит вставленные адреса и второй раз ссылку не создаст).

**Цена названа: ремоут рисуется от НАШЕГО корня, то есть крупнее,
чем задумал автор.** Иначе никак — `rem` считается от корня документа,
и сузить его до поддерева невозможно в принципе. Выбор между «поедет
админка» и «чужой экран крупнее» сделан в пользу второго: документ
наш, и гость не вправе его переопределять.

Новым ремоутам трогать `html` и `body` запрещено договором.

**Ремоут на Tailwind v3** (2026-09-24) принёс третью утечку, самую
широкую: его `<link>` — preflight и утилиты вне слоёв. `a { color:
inherit }` бил `text-fg-muted` в сайдбаре, `body { font-family: Inter }`
— шрифт всей админки, `* { border-color }` — прозрачную рамку карточки.
Сужение по поддереву здесь не годится: классы у v3 и нашего v4 те же,
а выпадашки ремоута живут порталом в `body` и остались бы без стилей.

Лечится слоем: ссылка ремоута глушится (`media="not all"`), а вместо неё
ставится `@import url(…) layer(remote)`. Слой `remote` объявлен между
нашими `base` и `utilities` (`app/styles.css`): внутри ремоута его
правила по-прежнему бьют наш сброс, снаружи — проигрывают нашим
утилитам. `body` вынесен из `base` вне слоёв, иначе его `body` победил бы.

**Цена: одноимённые классы с разным смыслом внутри ремоута теперь
наши.** У него `hover:bg-accent` — оранжевый, у нас `bg-accent` —
голубой, и побеждает наш. Обратное (чужой класс перекрашивает нашу
админку) хуже: гость не вправе переопределять документ.

## Последствия

**`react/jsx-runtime` теперь тоже общий — для договора 1.** Без него
JSX ремоута собирается его собственным рантаймом, а элемент чужого
поколения наш React 19 отвергает ошибкой #525. Ровно на этом сломался
первый заход (ADR-0005).

**`react-dom/client` в общую область НЕ кладём, и это запрет.** Ремоут
договора 1 живёт в нашем дереве и не имеет права заводить свой корень.
Попытка утащит вторую копию рендерера, и автор увидит это по размеру
сборки.

**Правило, которое стоит держать в голове:** `shared` ремоута
определяет, что он СПРОСИТ; общая область хоста — что он ПОЛУЧИТ.
Спросил и не нашёл — молча взял свою копию, и это самый неприятный вид
отказа: белый экран без единой ошибки. Поэтому списки с обеих сторон
совпадают буква в букву.

**Ремоут договора 1 обязан проставить `requiredVersion: "^19"`.** Без
него он попадёт в ветку «первая версия» и получит React 18. В пресете
SDK это не опция, а константа.

**Ремоут новее админки получает отказ словами**, а не белый экран:
`contract` больше известного хосту — на экране «собрано под более новую
версию админки». Порядок выката: сначала хост, потом ремоуты.

**Старое поколение поддерживается бессрочно.** Это не legacy-ветка по
флагу, которую правила репозитория запрещают, а совместимость с чужим
кодом, который мы не контролируем.

**Форма будущих ремоутов задаётся не только нами.** Пока шаблон в
GitLab, который форкает бэкенд, не переведён на SDK, каждый новый
микрофронтенд рождается старого поколения. Это отдельная задача в
чужом репозитории.
