# 1. Environment живёт в сессии, а не в URL

Дата: 2026-08-14
Статус: принято

## Контекст

Мы проектировали форму URL для нового фронтенда и по умолчанию хотели
положить в путь и проект, и окружение: `/p/:projectId/e/:envId/t/:tableSlug`.
Мотив был обычный: явный deep-link, окружение в ключах кэша, две вкладки
в разных окружениях.

Чтение бэкенда показало, что третий мотив недостижим.

`ucode_go_auth_service/grpc/service/session_service_v2.go`:

- `environment_id` **отсутствует** в claims JWT (строка 1813). В токене есть
  `project_id`, `role_id`, `client_type_id`, `user_id`, `tables`,
  `login_table_slug`, `client_platform_id`.
- Окружение передаётся заголовком `Environment-Id`
  (`ucode_go_admin_api_gateway/api/handlers/v2/middleware.go:44`) и хранится
  полем `EnvId` в строке сессии в БД.
- `V2RefreshTokenForEnv` (строка 2608) при смене окружения **мутирует ту же
  запись сессии** и выпускает новую пару access+refresh токенов.

Следствие: окружение — свойство одной серверной сессии, а не вкладки.
Переключение окружения в одной вкладке меняет окружение во всех и
ротирует токены остальных.

Кроме того, у Project нет slug (`projects_service.proto:237`) — только UUID
и произвольный `name`. Оба сегмента были бы UUID: ~115 символов в адресной
строке.

## Решение

Форма URL:

```
/p/:projectId/t/:tableSlug?view=<viewId>&page=&sort=&filter=
```

- Путь — **что** смотрим: проект и таблица.
- Query — **как** смотрим: view, фильтры, сортировка, пагинация.
- Окружение в URL **отсутствует полностью**. Берётся из сессии.
- Смена окружения — `V2RefreshTokenForEnv` + `queryClient.clear()` +
  навигация. Не переключатель, а переход.

## Последствия

**Принимаем:** пользователь находится ровно в одном окружении во всех
вкладках браузера одновременно. Ссылка не несёт окружения — открывший её
увидит данные своего текущего окружения. Это осознанно принятое
ограничение v1, а не недосмотр.

**Получаем:** URL вдвое короче; адресная строка не обещает измерения,
которого не существует; правило «в URL живёт состояние отображения»
остаётся без исключений.

**Чинится только на бэкенде:** сделать `Environment-Id` чистым заголовком
запроса без мутации серверной сессии. Тогда окружение можно будет вернуть
в URL и получить мульти-таб. До тех пор фронтенд это не решает.

## Альтернативы

- **`/e/:envId` в пути** — отвергнуто: обещает мульти-таб, которого нет.
- **`?env=` в query для шаринга** — отвергнуто: обмена ссылками между
  окружениями в реальной работе нет, а параметр требовал бы диалога
  «переключиться?» при несовпадении.
- **Слаги вместо UUID** — недоступно: у Project нет поля slug.

## Дополнение от 2026-08-14: путь ключуется на menuId

При работе над сайдбаром выяснилось, что `/t/:tableSlug` из решения выше
не соответствует API.

**Набор View принадлежит пункту меню, а не таблице:**
`GET /v3/menus/{menuId}/views` (`ucode_go_admin_api_gateway/api/api.go:904`).
Два пункта меню могут показывать одну Table с разными наборами View.
Слаг таблицы такой пункт не идентифицирует.

Новый роутер старого ucode пришёл к тому же — там везде `:menuId`
(`router/NewRouter.jsx`).

**Project тоже уходит из пути** — по той же логике, что и Environment
в основном решении. Проект лежит в claim токена, смена проекта выпускает
новую пару токенов и мутирует ту же серверную сессию. Значит, двух
проектов одновременно не бывает, и путь `/p/:projectId` обещал бы
измерение, которого нет.

Итоговая форма:

```
/m/:menuId?view=<viewId>&page=&sort=&filter=
```

Путь — какой пункт меню открыт. Query — как показан. Project
и Environment — в сессии.

Всё остальное в решении выше остаётся в силе: смена окружения — переход
с ротацией токенов и `queryClient.clear()`, мульти-таб на разных
окружениях невозможен.
